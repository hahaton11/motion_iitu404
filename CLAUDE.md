# Motion Board — правила для агентов

Жестовая доска для брейншторма. Хакатон Admit, кейс «Камера вместо джойстика».
Дедлайн сдачи: 30.09, 15:00 UTC+5. Заморозка фич: 30.09, 12:00.

## Продукт в одном абзаце

Пользователь стоит перед экраном и управляет доской руками, как Тони Старк голограммой.
Прицел-горошина следует за центром ладони, рука в покое ставит его на паузу. Сжал кулак — взял
элемент, дальше он прилипает к руке при любой позе. Кулак и быстрое раскрытие на месте — положить,
то же на резком махе — выбросить. Два пальца — двигать доску, щипок и движение вверх-вниз — масштаб.
Внизу экрана карман: элемент падает в него после короткой задержки над ним, достают кулаком.
Заготовки в карман можно положить заранее мышью. Текст стикеров надиктовывается голосом: указать
пальцем на стикер и задержать. Позы распознаёт kNN-классификатор, обученный на записях живых рук.
Если жест неточный, система говорит, что именно исправить.

## Критерии жюри, под которые всё делается

Работоспособность 30, режим «ошибка» 20, техническая реализация 20, UX 15, оригинальность 10, бонусы 5.
Если жюри не откроет деплой, за работоспособность 0. Поэтому деплой и сквозной сценарий важнее красоты.

## Стек

- Vite + TypeScript strict, без UI-фреймворков. Доска на DOM + CSS transforms.
- `@mediapipe/tasks-vision`, HandLandmarker, GPU delegate с fallback на CPU.
- Vitest для всей чистой логики. Playwright только для смоук-тестов в S5.
- Деплой: GitHub Pages через `.github/workflows/deploy.yml`, `base: './'`.

## Архитектура

```
src/contracts/input.ts   контракт событий, единственная точка стыковки модулей
src/shared/              emitter, velocity, константы, MouseInput — эмулятор жестов мышью
src/motion/              S1: CameraInput implements InputSource
src/board/               S2: холст, элементы, прицел, захват, падение, бросок
src/pocket/              S3: карман и режим подготовки
src/voice/               S3: голосовой ввод текста
src/app/                 S4: онбординг, калибровка, челлендж, финал, рекорды, звук
```

Потребители знают только `InputSource`. Доска не импортирует ничего из `src/motion`, камера ничего из `src/board`.
Весь UI разрабатывается и тестируется на `MouseInput`, камера подключается в S4 одной строкой.

## Правила кода

- Трогать только файлы своей зоны из ТЗ. Контракт `src/contracts/input.ts` не менять.
  Если без изменения контракта никак, добавить новое поле как опциональное и написать об этом в отчёте.
- Иммутабельные данные: состояние обновляется новой копией, `readonly` в типах.
- Функции до 50 строк, файлы до 400, вложенность до 3 уровней.
- Чистая логика отдельно от DOM и камеры, чтобы покрываться тестами без браузера.
- Все пороги и тайминги в константах модуля, никаких магических чисел в логике.
- Никаких `console.log` в итоговом коде.
- Интерфейс на русском. Каждая подсказка отвечает на вопрос «что сделать», а не «что не так».
  Плохо: «Жест не распознан». Хорошо: «Сожми кулак полностью, чтобы взять».

## Процесс сессии

1. Прочитать этот файл и свой `docs/specs/Sx.md`.
2. Писать тест, потом реализацию, для каждой единицы чистой логики.
3. После каждого логического шага: `npm test && npm run build`, затем коммит.
4. Коммиты маленькие, conventional commits: `feat(board): drop animation`. Жюри смотрит историю.
5. В конце сессии пройти чек-лист приёмки из ТЗ и написать короткий отчёт:
   что сделано, что не сделано, какие решения приняты, что проверить человеку руками.

## Определение «готово»

`npm test` зелёный, `npm run build` без ошибок, демо-страница сессии работает в Chrome,
все пункты приёмки из ТЗ отмечены или явно перечислены как невыполненные.
