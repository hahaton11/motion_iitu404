### Что сделано в ночь на 04.10

**Обучение стало семишаговым: у панорамы и зума теперь свои задания.** Оба жеста
были в продукте с 3 октября, но показать их было негде — в задании про перенос
стикера они не встречаются, и человек просто не узнавал, что доску можно двигать
и масштабировать. Шаг панорамы: у правого края висит метка, её надо привести
в середину экрана. Шаг зума: в центре табличка, подпись на ней набрана семью
пикселями и в масштабе 1 физически не читается.

Прохождение этих двух шагов видно только по камере доски — отдельных событий
панорамы и зума наружу нет. Решение принимается, когда камера постояла 420 мс:
по каждому кадру судить нельзя, подсказка «веди дальше» вылетала бы посреди
движения, а шаг засчитывался бы на первом же кадре, попавшем в цель.

**Подсказки на два тупика новых жестов.** Оба можно показать правильно и не получить
ничего — это неотличимо от поломки. `PINCH_SIDEWAYS`: щипок ведут вбок, где масштаб
не меняется намеренно. `CARRY_NAV_BUSY`: два пальца или щипок рукой, которая несёт
элемент, — жесты доски при переносе выключены, чтобы доска не уезжала из-под элемента.

Первая версия `PINCH_SIDEWAYS` молчала ровно так же, как её отсутствие: флаг ставился
только на кадрах, где рука шла и вбок, и немного по вертикали, а ровный ход в сторону
отсекался мёртвой зоной до всякой проверки осей. Поймал это интеграционный тест
на всём конвейере — чистая функция была «права».

**Найден и закрыт дефект ввода мышью.** После зума Alt-перетаскиванием курсор оставался
стоять лупой навсегда: доска работала, а рука к ней больше не относилась — карман
не открывался, элементы не брались. Chrome не доставил `pointerup`, пришедший с зажатым
Alt, и жест для приложения не кончился. Теперь движение с ненажатой кнопкой заканчивает
и панораму, и зум, чем бы ни было потеряно отпускание.

**Визуал.** Пока доска масштабируется, в углу стоит цифра масштаба в процентах:
у зума щипком нет другой опоры. И `overflow-wrap: anywhere` больше не рвёт слова
посреди корня — на челлендже это читалось как «Ретранслят/ор поднят».

**Появился прогон по всему функционалу с записью видео**: `e2e/walkthrough.spec.ts`,
отдельный проект Playwright. В смоук не входит — медленный нарочно, с паузами
на чтение карточек. Нужен ради самой записи: на финале это запасной ролик, если
не встанет камера или не будет света.

## Запуск

```
npm ci
npx playwright install chromium
npm run dev          # http://localhost:5173
npm test             # 551 unit-тест
npm run build
npm run e2e          # смоук, видео-тест пропускается без test-assets/gestures.y4m
npx playwright test --project=walkthrough   # прогон по всему функционалу с записью
```

Страницы: `index.html` — продукт целиком. `motion.html` — отладка распознавания
с цифрами. `board.html`, `pocket.html` — демо. `record.html` — запись датасета.
`?input=camera` включает руку на демо-страницах, `?input=mouse` — мышь на главной.

### Инструменты замера

```
npx tsx scripts/measure-fps.ts            # FPS доски, 50 элементов, панорама и зум
npx tsx scripts/eval-gestures.ts data/gestures-v5-pinch.json
motion.html?w=640&h=360&delegate=cpu      # сравнение вариантов распознавания без пересборки
```

Производительность распознавания меряется в `motion.html`: карточка «Кадр» показывает
FPS, задержку обработки, делегат и настоящий размер потока. Так нашлось, что конвейер
упирается в распознавание, а не в камеру: 62 мс на вызов при 1280×720 запирают цикл
на 16 кадрах, и две руки стоят столько же, сколько одна.

## Пороги, которые проверяются только руками

Всё в `src/motion/constants.ts`, если не указано иное.

- `THROW_SPEED` и `THROW_MEMORY_MS` в `src/shared/constants.ts`: улетает ли намеренный
  мах и не улетает ли спокойное отпускание после быстрого переноса.
- `PINCH_ZOOM_GAIN 2.5`: хватает ли одного хода руки, чтобы приблизить доску вдвое.
- `PINCH_SIDEWAYS_MIN 0.04` и `PINCH_SIDEWAYS_HINT_MS 700`: не приходит ли подсказка
  про ход вбок к тому, кто просто держит щипок неподвижно.
- `CARRY_NAV_HINT_MS 700`: не частит ли подсказка про элемент в руке.
- `TUTORIAL_ZOOM_GOAL 1.6` и `TUTORIAL_PAN_TARGET` в `src/app/tutorial.ts`: сколько
  подходов рукой нужно, чтобы пройти шаг. Эмулятору хватает одного.
- `VOTE_THRESHOLD 0.75` в `src/gestures/voter.ts`: после переобучения модели
  порог стоит перепроверить скриптом оценки.
- `ASSET_BYTES` в `src/motion/loading.ts`: после пересборки модели цифру `gestures`
  надо обновить, иначе полоса загрузки врёт на пару процентов.

## Известные ограничения

- Модель обучена на одном человеке и на одной руке; для другого её стоит переобучить,
  порядок команд в README.
- Undo нигде не подключён: после «положить в карман» он дублировал бы элемент.
- Голосовой ввод требует Chrome и сети; без него текст готовится заранее мышью.
- Хук `block-no-verify` из плагина ECC принимает флаг `-n` у любой утилиты
  в одной команде с `git commit` за `--no-verify`. Коммитить отдельной командой.
