# Motion Board

Пульт, до которого не нужно дотягиваться: экраном управляют руками через веб-камеру.
Открывается по ссылке в браузере: ничего не ставить, ничего не подключать, никаких ключей.

**Демо: https://hahaton11.github.io/motion_iitu404/**

**Презентация (PDF): https://hahaton11.github.io/motion_iitu404/presentation.pdf**

**Видео работы: https://hahaton11.github.io/motion_iitu404/demo.webm**

## Зачем это

Есть экраны, до которых нельзя дотронуться.

Хирург у монитора в стерильной зоне. Повар с мокрыми руками. Механик в перчатках.
Инженер в чистой комнате. Ведущий воркшопа, который стоит у большой панели перед
группой и не хочет возвращаться к ноутбуку за каждым действием. Класс, где экран
один, а руки — двадцать, и общая мышь это способ передать простуду.

Во всех этих случаях мышь недоступна не потому, что жесты моднее, а потому что
**мыши физически нет под рукой**. Тач-панель на большой экран стоит денег, камера
уже встроена в любой ноутбук и стоит ноль.

Motion Board — это ответ на вопрос «как работать с экраном, не касаясь его»,
на задаче, где это действительно нужно: разложить идеи по группам. Брейншторм
выбран потому, что это работа **стоя и в движении**, с крупными объектами,
где точность попадания в пиксель не нужна, а размах руки естественен.

Что из этого следует для проекта: мы оптимизируем не «сколько жестов система
знает», а **сколько минут ей можно пользоваться, не устав**. Раздел
[«Эргономика»](#эргономика-почему-рука-не-устаёт) — про то, как это сделано,
и это главное инженерное содержание работы.

## Запуск

```bash
npm ci
npm run dev          # http://localhost:5173
```

```bash
npm test             # 551 unit-тест
npm run build        # tsc --noEmit && vite build
npx playwright install chromium
npm run e2e          # смоук-тесты
npm run deck         # пересобрать презентацию в public/presentation.pdf
```

**Требования:** Chrome или Edge, камера, разрешение на камеру и микрофон.
Голосовой ввод текста работает только в Chrome. Без микрофона всё остальное
работает, текст можно подготовить заранее мышью. Подробнее в разделе «Голос и разрешения».

Страницы: `index.html` — продукт целиком. `motion.html` — отладка распознавания
с цифрами. `board.html`, `pocket.html` — демо доски и кармана. `record.html` —
запись своего датасета жестов. На любой демо-странице `?input=camera` включает
руку, на главной `?input=mouse` — эмулятор жестов мышью.

## Жесты

| Жест | Действие |
|---|---|
| **Кулак** | взять элемент под прицелом. Элемент прилипает к руке и едет за ней в любой позе |
| **Кулак и сразу ладонь** на месте, быстрее 0,6 с | положить — элемент падает с анимацией |
| **Кулак и сразу ладонь на ходу**, на резком махе | элемент улетает и удаляется |
| **Элемент над карманом**, задержать 0,3 с | элемент ложится в карман сам, карман заполняется полоской |
| **Указательный палец** + задержка 1 с | нажать кнопку на плашке: копия, цвет, удалить |
| **Рука в покое** | ничего. Курсор встаёт на паузу, можно отдохнуть |
| **Два пальца** — указательный и средний вытянуты, остальные согнуты, и повести рукой | панорама: доска едет за рукой, прицел становится крестиком и стоит на месте |
| **Щипок** — большой и указательный сомкнуты, остальные согнуты, и повести рукой вверх или вниз | зум доски: вверх — ближе, вниз — дальше, вокруг точки, где сомкнулся щипок. Прицел становится лупой «±» и стоит на месте |
| **Две руки в кулаке** без элементов, свести и развести | тоже зум доски |
| **Открытая ладонь над карманом**, задержать | карман открывается |
| **Указательный палец** + задержка на стикере, затем **голос** | диктовка текста в стикер, подробнее в разделе «Голос и разрешения» |

Прицел следует за центром ладони. Под взятым элементом висит его тень —
по ней видно высоту подъёма. Пока доска масштабируется, в углу стоит цифра
масштаба в процентах и уходит через 1,1 с: у зума щипком нет другой опоры —
рука ведёт вверх, доска растёт, и сказать, где ты сейчас, больше нечем.

Захват, перенос и отпускание разведены, чтобы случайное движение ничего
не роняло и не удаляло:

- **Взять** — сжать кулак. Элемент прилипает к руке.
- **Нести** — рука может раскрыться, расслабиться, сложиться в щипок или два
  пальца: элемент остаётся в руке, прицел и элемент идут за рукой. Пока элемент
  в руке, щипок не зумит, а два пальца не двигают доску: форма кисти во время
  переноса — не команда.
- **Положить** — «щелчок»: снова сжать кулак и сразу раскрыть ладонь. Окно
  `PUT_WINDOW_MS = 600` мс от кулака до ладони. Кулак, продержанный дольше,
  тоже кладёт, но только кладёт: удаление требует быстрого щелчка. Раскрытая
  ладонь без кулака перед ней не делает ничего.
- **Удалить** — тот же щелчок на резком махе: скорость руки выше `THROW_SPEED`.
  Быстрый перенос без щелчка ничего не удаляет.
- **В карман** — поднести элемент к карману и задержать на `STASH_DWELL_MS = 300` мс.
  Карман подсвечивается и заполняется, пока идёт задержка; пронёс мимо быстрее —
  ничего. Щелчок над карманом кладёт в карман сразу.
- **Рука пропала** из кадра во время переноса — элемент падает на месте.
  Удаляет пропажа руки только щелчок, взведённый в окне: рука как раз теряется
  на резком махе.

Жесты разведены: кулак берёт, два пальца двигают доску, щипок масштабирует.
Кулак на пустом месте ничего не делает, а если его тянуть, система подсказывает
показать два пальца. Щипок элементы не берёт: если сомкнуть его над элементом
и держать без движения дольше секунды, система подсказывает сжать кулак.
В эмуляторе мышью клик по элементу берёт его, элемент едет за мышью без
зажатой кнопки, второй клик кладёт, клик на быстром ходу удаляет, задержка
над карманом убирает в карман. Панорама — перетаскивание правой или средней
кнопкой либо левой с зажатым пробелом, зум — колесо или Alt и перетаскивание
вверх-вниз.

## Голос и разрешения

**Разрешения спрашиваются сразу при входе.** В режиме камеры приложение просит
камеру и микрофон одним запросом `getUserMedia({ video, audio })`, поэтому браузер
показывает одно окно на оба. Звуковые дорожки сразу останавливаются: сам звук
не нужен, а Web Speech API потом пользуется уже выданным разрешением и второй раз
не спрашивает. Если общий запрос не прошёл, камера просится отдельно, и отказ
в микрофоне её не выключает. В режиме мыши `?input=mouse` микрофон спрашивается
отдельным окном на старте. Код: `src/motion/camera.ts` (`acquireCamera`),
`src/shared/microphone.ts`, состояние в `src/app/app.ts`.

**Статус виден на старте и на экране камеры:** «Камера ✓ · Микрофон ✓». Если
микрофон запрещён, рядом написано, что сделать: нажать на значок слева
в адресной строке, разрешить микрофон и обновить страницу. Голос при этом
выключен, всё остальное работает. Тексты в `src/app/permissions.ts`.

**Как продиктовать текст в стикер:**

1. Укажи на стикер указательным пальцем и задержи руку. С мышью: Shift
   и удержание левой кнопки на стикере.
2. Появится красное кольцо и плашка «Говори, я записываю». Скажи текст.
3. Замолчи на полторы секунды или укажи на стикер ещё раз — текст запишется.

Под стикером, на который наведён прицел, и под выделенным стикером висит
подсказка с этим жестом. Если микрофон запрещён или браузер не умеет
распознавать речь, подсказка говорит, что включить. Последний шаг обучения
«Продиктуй текст» учит этому жесту; без голоса шаг засчитывается за сам жест.

## Эргономика: почему рука не устаёт

Жестовые интерфейсы проваливаются не на точности распознавания, а на
**gorilla arm** — усталости от поднятой руки. Через две минуты держать руку
перед собой физически тяжело, и пользователь бросает. Поэтому четыре решения
в этом проекте существуют ровно ради усталости, а не ради красоты.

**Рабочий бокс.** Курсор считается не по всему кадру, а по центральному квадрату
в половину кадра по каждой стороне: `POINTER_BOX = { w: 0.5, h: 0.5 }`. Движение
кисти на 20 сантиметров покрывает весь экран. Руку не нужно разводить в стороны
и поднимать выше плеча — она работает в зоне перед грудью, где её держать легче
всего.

**Класс «бездействие».** Опустить руку и отдохнуть — это не выход из приложения.
Классификатор обучен на отдельном классе «рука есть, но человек не действует»:
курсор встаёт на паузу, ничего не берётся и не падает. Это то, чего нет в
системах на правилах: там расслабленная рука неизбежно попадает в какой-нибудь
жест. Цифры — в [разделе про распознавание](#как-устроено-распознавание).

**Магнитный фокус.** Элемент в радиусе 80 px от прицела берётся без точного
попадания (`FOCUS_RADIUS_PX = 80`). Целиться в объект дрожащей рукой на весу —
самая утомительная часть любого жестового интерфейса, и она здесь убрана.

**Крупные цели.** Кнопки плашки 76×44 px, карман — полоса во всю ширину экрана
внизу. Попадание в них не требует точности.

Плюс к этому **фильтр One Euro** (`ONE_EURO_MIN_CUTOFF = 0.8`, `ONE_EURO_BETA = 5`):
сглаживание тем сильнее, чем медленнее движение. На медленном прицеливании
дрожание убирается, на резком броске фильтр отпускает и не создаёт отставания.
Дрожащий курсор заставляет напрягать руку — это тоже усталость.

## Обучение: семь заданий

Жест, которому не дали задания, человек не находит. Поэтому каждый жест учится
на своём шаге, и шаг кончается не по времени, а по сделанному делу —
`src/app/tutorial.ts`, чистый редьюсер поверх событий доски и кармана.

| Шаг | Что просят | Чем засчитывается |
|---|---|---|
| Возьми и перенеси | кулак, донести до рамки, щелчок кулак → ладонь | элемент лёг центром в рамку |
| Выброси в шлюз | тот же щелчок, но на резком махе | элемент удалён броском |
| **Подвинь доску** | два пальца, вести рукой в сторону | метка у правого края приведена в середину экрана |
| **Приблизь доску** | щипок, вести рукой вверх | масштаб дошёл до 1.6, и мелкая надпись на табличке стала читаемой |
| Достань из кармана | ладонь над карманом, затем кулак над карточкой | карточка в руке |
| Убери в карман | поднести к карману и задержать | карман забрал элемент |
| Продиктуй текст | указать пальцем, задержать, говорить | текст записан в стикер |

Шаги идут группами: сначала то, что делают с элементом, потом то, что делают
с самой доской, потом карман и голос.

Два шага навигации проверяются не событием, а камерой доски: отдельных событий
панорамы и зума наружу нет, доска показывает их только положением и масштабом.
Решение принимается, когда камера постояла 420 мс, — по каждому кадру судить
нельзя: подсказка «веди дальше» вылетала бы посреди движения, а шаг засчитывался бы
на первом же кадре, попавшем в цель.

На каждом шаге на свои ошибки есть свои подсказки, они в таблице ниже. Любой шаг
пропускается кнопкой: застрявший человек на демо хуже непройденного шага.

## Режим «ошибка»

Принцип: **каждая подсказка отвечает на вопрос «что сделать», а не «что не так».**
Не «жест не распознан», а «сожми кулак полностью, чтобы взять».

Технически подсказки устроены так, чтобы не мешать: условие должно продержаться
заданное время, и один код повторяется не чаще раза в 3 секунды
(`HINT_COOLDOWN_MS = 3000`). Мигающая подсказка хуже отсутствующей.

### Распознавание руки — `src/motion/hints.ts`

| Код | Условие | Текст |
|---|---|---|
| `NO_HAND` | рук в кадре нет 3 с | Подними руку перед камерой, ладонью к экрану |
| `TOO_FAR` | размер ладони < 0.07 кадра, 0,3 с | Подойди на шаг ближе к камере |
| `TOO_CLOSE` | размер ладони > 0.32 кадра, 0,3 с | Отойди на шаг назад, рука не помещается в кадр |
| `HAND_NEAR_EDGE` | рука ближе 5 % кадра к его краю, 0,3 с | Рука у края кадра, веди её ближе к центру |
| `POOR_TRACKING` | уверенность детектора < 0.6, 1 с | Мало света, повернись к источнику света |
| `MOVING_TOO_FAST` | рука потеряна на высокой скорости | Двигай рукой чуть медленнее, камера не успевает |
| `HALF_GRAB` | поза между кулаком и ладонью 0,5 с, элемент не взят | Сожми кулак полностью, чтобы взять |
| `HALF_RELEASE` | то же в щелчке «кулак → ладонь» или кулаке без элемента | Раскрой ладонь шире, чтобы отпустить |
| `CARRY_PUT_HOW` | элемент в руке, ладонь раскрыта 3,5 с | Чтобы положить, сожми кулак и быстро раскрой ладонь |
| `CARRY_THROW_HOW` | резкий мах с элементом без щелчка | Чтобы выбросить, сожми кулак и раскрой ладонь на ходу |
| `CARRY_THROW_SLOW` | щелчок на махе дольше окна: элемент положен, а не выброшен | Чтобы выбросить, раскрой ладонь сразу после кулака, не задерживая его |
| `CARRY_NAV_BUSY` | два пальца или щипок рукой, которая несёт элемент, 0,7 с | Сначала положи элемент щелчком кулак → ладонь, потом двигай доску |
| `HALF_PAN` | два пальца видны неуверенно 0,6 с | Выпрями указательный и средний, остальные согни |
| `HALF_PINCH` | щипок виден неуверенно 0,6 с | Сомкни кончики большого и указательного, остальные пальцы согни |
| `PINCH_SIDEWAYS` | щипок держат и ведут вбок 0,7 с: масштаб не меняется | Веди щипок вверх или вниз: в сторону масштаб не меняется |
| `SWIPE_SHORT` | взмах короче порога | Махни шире, примерно на полруки, чтобы перейти |
| `SWIPE_DIAGONAL` | взмах по диагонали | Махни строго вбок или строго вверх-вниз |

| Код | Условие | Текст |
|---|---|---|
| `BOARD_RELEASE_EDGE` | элемент положен за краем доски | Клади элемент над доской, а не за её краем |
| `BOARD_TOOLBAR_POINT` | кулак по кнопке плашки | Укажи на кнопку одним пальцем и задержи руку, чтобы выбрать действие |
| `BOARD_ZOOM_MAX` | упор в максимальный зум | Сведи руки, чтобы отдалить доску; при щипке — Веди щипок вниз, чтобы отдалить доску |
| `BOARD_ZOOM_MIN` | упор в минимальный зум | Разведи руки, чтобы приблизить доску; при щипке — Веди щипок вверх, чтобы приблизить доску |
| `BOARD_GRIP_PAN` | кулак на пустом месте тянут | Чтобы двигать доску, покажи два пальца — указательный и средний |
| `BOARD_PINCH_GRAB` | щипок над элементом стоит без зума дольше 1 с, не чаще раза в 5 с | Чтобы взять элемент, сожми кулак. Щипок с движением вверх или вниз меняет масштаб |

## Как устроено распознавание

```
камера → HandLandmarker → признаки в системе координат ладони → One Euro
       → kNN → голосование 4 из 6 кадров → машина состояний → событие
```

**Точки.** MediaPipe `HandLandmarker`, 21 точка на кисть, GPU-делегат с откатом
на CPU. Модель и WASM лежат в `public/`, а не берутся с CDN: приложение работает
без интернета после загрузки.

**Признаки.** Точки переводятся в **систему координат ладони** — начало в запястье,
оси по самой ладони. После этого признаки не зависят от того, где рука в кадре,
как она повёрнута и насколько далеко находится. Это делает основную работу:
классификатору не приходится учить одно и то же положение пальцев во всех
позициях кадра.

**Сглаживание.** Фильтр One Euro на координатах прицела, адаптивный по скорости.

**Классификация.** kNN по записанным примерам, 6 классов: `idle`, `open`, `fist`,
`pinch`, `point`, `victory`. Порог уверенности 0.75.

**Голосование.** Класс считается установленным, когда продержался **3 кадра из 6**;
бездействию нужно 4 — оно не перебивает жест, который наблюдался. Это убирает
мигание на границе между классами ценой задержки около 180 мс.

**Панорама.** Пока устойчивая поза `victory` и рука ничего не держит, pipeline
шлёт событие `pan` со сдвигом сглаженной точки руки, а курсор стоит на месте.
Первый кадр жеста только ставит точку отсчёта, поэтому путь руки, пройденный,
пока голосование набирало кадры, в панораму не попадает и доска не дёргается.
Кадры, где сырая поза уже не `victory` — пальцы складываются, — ничего не
сдвигают: смена формы кисти смещает центр ладони, и это не движение руки.
Дрожь меньше `PAN_MIN_STEP` гасится без потери медленного хода. `victory`,
увиденная с уверенностью от 0.4 до порога дольше `NEAR_PAN_HINT_MS`, даёт
подсказку «Выпрями указательный и средний, остальные согни».

**Зум щипком.** Пока устойчивая поза `pinch` и рука ничего не держит, pipeline
шлёт событие `zoom` с `factor = exp(-dy · PINCH_ZOOM_GAIN)`, где `dy` —
вертикальный сдвиг сглаженной точки руки в долях экрана. Экспонента делает ход
вверх и вниз на одно расстояние взаимно обратным: рука вернулась — масштаб тоже.
Центр масштаба — курсор в момент, когда щипок сомкнулся; курсор на время зума
стоит и в событии `cursor` помечен `zooming`. Как у панорамы, первый кадр только
ставит точку отсчёта, кадры со сменой формы кисти не считаются, дрожь меньше
`PINCH_ZOOM_DEAD_ZONE` гасится без потери медленного хода, а шаг вбок, где
горизонталь в `PINCH_ZOOM_AXIS_RATIO` раз длиннее вертикали, не зумит и не
панорамирует. Во время зума двумя кулаками щипок молчит. Неуверенный `pinch`
дольше `NEAR_PINCH_HINT_MS` даёт подсказку «Сомкни кончики большого
и указательного, остальные пальцы согни».

**Машина состояний** (`src/motion/hand-state.ts`). Захват управляется позой
через гистерезис: **кулак берёт**, **бездействие и щипок не меняют ничего**.
Машина видит только `closure`: кулак даёт 1, ладонь 0, щипок и бездействие —
значение между порогами. Два порога вместо одного — состояние не дребезжит
на границе.

```
open → closing → holding ⇄ opening → open           кулак на пустом месте
                    ↓ доска взяла элемент
                 holding → carrying → clicking → open  перенос и щелчок
```

Машина не знает, что лежит под прицелом, поэтому захват прилипает только по
ответу потребителя: доска вызывает необязательный `InputSource.setCarrying(hand,
true)`, когда элемент оказался в руке, и `false`, когда он ушёл из руки без жеста —
в карман или в удаление. Без ответа кулак ведёт себя по-старому: раскрытая
ладонь его отпускает. Так работает кулак на пустом месте и зум двумя кулаками.

С элементом в руке раскрытие захватного кулака переводит руку в `carrying`:
поза больше не важна. Кулак, продержавшийся 3 кадра, взводит щелчок (`clicking`),
раскрытая ладонь после него решает: от первого кадра кулака до первого кадра
ладони не дольше `PUT_WINDOW_MS` — `release` на месте или `throw` на махе;
дольше — только `release`. Обе позы приносит голосователь с одной и той же
задержкой, поэтому она вычитается, и окно мерит, сколько кулак держали на самом деле.

**Бросок** решается не скоростью в момент раскрытия ладони, а **самой быстрой
скоростью за последние 450 мс**. Причина в задержке: позу приносит голосователь,
которому нужно 4 уверенных кадра, и к этому моменту мах уже кончился. Окно
сбрасывается на захвате, чтобы мах, которым рука дотянулась до элемента,
не засчитывался броском. Мах без щелчка с элементом в руке не удаляет,
а подсказывает, как выбросить.

**Калибровка** под конкретного человека и освещение проходит при запуске.

Если модель не загрузилась, включаются прежние правила по углам пальцев —
приложение деградирует, но продолжает работать.

### Почему обученная модель, а не правила

Версия 1 распознавала жесты правилами по углам пальцев. Версия 2 — обученным
kNN. Замена сделана не ради «использовать ML», а из-за одной конкретной проблемы:
**правила не умеют молчать.**

Оценка на отложенном круге записи, который не участвовал в обучении
(`scripts/eval-gestures.ts`, `data/gestures-v4.json`):

**Правила по углам пальцев**

| истина \ ответ | idle | open | fist | pinch | point | victory | recall |
|---|---|---|---|---|---|---|---|
| **idle** | 105 | 234 | 23 | 0 | 5 | 0 | 28.6 % |
| **open** | 0 | 222 | 0 | 0 | 0 | 0 | 100 % |
| **fist** | 29 | 0 | 196 | 0 | 0 | 0 | 87.1 % |
| **pinch** | 137 | 47 | 29 | 0 | 0 | 0 | **0 %** |
| **point** | 7 | 3 | 80 | 0 | 63 | 0 | 41.2 % |
| **victory** | 57 | 118 | 0 | 0 | 0 | 0 | **0 %** |

Общая точность 43.2 %. **Ложные действия на бездействии: 71.4 %** — 262 кадра
из 367. Спокойно опущенная рука читалась как команда в семи случаях из десяти.
Щипок и жест V правила не видят вовсе.

**kNN + голосование по окну** — то, что стоит в продукте

| истина \ ответ | idle | open | fist | pinch | point | victory | recall |
|---|---|---|---|---|---|---|---|
| **idle** | 325 | 25 | 0 | 17 | 0 | 0 | 88.6 % |
| **open** | 2 | 220 | 0 | 0 | 0 | 0 | 99.1 % |
| **fist** | 2 | 0 | 223 | 0 | 0 | 0 | 99.1 % |
| **pinch** | 12 | 0 | 0 | 201 | 0 | 0 | 94.4 % |
| **point** | 9 | 0 | 0 | 0 | 144 | 0 | 94.1 % |
| **victory** | 2 | 0 | 0 | 0 | 0 | 173 | 98.9 % |

Общая точность 94.9 %. **Ложные действия на бездействии: 11.4 %** — 42 кадра из 367.

Главная цифра здесь не точность, а верхняя строка обеих таблиц: 71.4 % против
11.4 %. Система, которая ошибается в сторону бездействия, ощущается надёжной.
Система, которая ошибается в сторону действия, ощущается сломанной — элемент
улетает сам собой, и пользователь не понимает почему.

Слабые места видны и названы. `pinch` и `point` уходят в `idle` в 5–6 % кадров:
захват иногда приходится повторить, и это заметно. Обратная ошибка — 17 кадров
покоя, прочитанных как щипок, — дороже, и именно она ограничивает, насколько
дальше можно двигать пороги.

**Эта таблица измеряет статику.** Протокол записи показывает каждую позу отдельно
и почти неподвижно, поэтому броска в нём нет вообще.

### Второй инструмент: разбор живого движения

Статичного набора не хватает, и это выяснилось дорого. Бросок чинили трижды —
запоминанием пиковой скорости, порогом, режимом голосователя — и каждый раз мимо,
потому что проверяли на данных, в которых броска не было.

Поэтому есть второй измеритель. `motion.html` пишет фикстуру: каждый кадр с сырыми
точками плюс события, которые сработали. `scripts/diagnose-throw.ts` прогоняет
её через тот же конвейер с той же моделью и печатает покадрово, что распознал
классификатор, с какой уверенностью, что получил голосователь, какой `closure`
дошёл до машины состояний, какая была скорость и в какой фазе она застряла.

На записи из десяти бросков это показало настоящую причину за один прогон.
Классификатор **распознавал раскрытую ладонь** — 68 кадров из 305, уверенно, —
но устойчивая поза не становилась `open` ни разу: элемент держался с второй
секунды по двадцатую. Дело было не в скорости и не в пороге. Бездействие
соперничало с ладонью на равных (`idle, idle, open, idle, open, open` — три
против трёх, большинства нет ни у кого), а сама ладонь раскрыта 2–3 кадра,
и один кадр с уверенностью 0.71, отброшенный порогом 0.75, ломал серию.

Оттуда обе правки: бездействие больше не перебивает жест, который наблюдался,
и планка уверенности снижается, **пока рука летит**. «Летит» — это запомненный
пик скорости, а не текущая: к моменту, когда ладонь раскрывается, рука уже стоит.

Замер на обоих инструментах сразу, против того, что было:

| | бросков из десяти | ложные действия на покое |
|---|---|---|
| было | 1 | 22.9 % |
| **стало** | **3** | **11.4 %** |

Втрое больше сработавших бросков и вдвое меньше ложных отпусканий одновременно.
Цифра в три из десяти — честная и не окончательная: раскрытие ладони занимает
150 мс, и при 17 кадрах в секунду больше голосов взять неоткуда. Это упирается
в частоту кадров, а она упирается в 62 мс на вызов детектора.

### Что делает кадр, в котором классификатор не уверен

Этот вопрос оказался важнее, чем выглядит, и ответ на него менялся дважды —
каждый раз потому, что менялись данные, на которых его можно было проверить.

Три политики на одних и тех же отложенных данных:

| кадр ниже порога | точность | ложные действия на idle |
|---|---|---|
| **голосует за бездействие** | **94.9 %** | **11.4 %** |
| занимает место, не голосует | 92.3 % | 25.9 % |
| не попадает в окно вовсе | 94.5 % | 16.3 % |

Ответ на этот вопрос менялся дважды, и оба раза не потому, что менялось мнение,
а потому что менялись данные, на которых его можно было проверить.

Какое-то время в продукте стояла вторая строка: низкая уверенность есть отсутствие
показаний, а не показание в пользу покоя. Обратной стороны того размена **не было
видно в данных** — в той записи отсутствовал класс `none`, кадры руки, которая
просто двигается, ничего не показывая. Бездействие было представлено одной
спокойной ладонью, и ложные действия выходили нулевыми у любой политики.

Когда `none` появился, оказалось, что пропуск неуверенного кадра дальше в действие
стоит **каждого четвёртого ложного отпускания**: элемент выпадает из руки, когда
её опускают отдохнуть. Голосование за покой безопасно по конкретной причине —
поза `idle` даёт `closure` 0.6, **между** порогами 0.45 и 0.75. Держащая рука
не роняет элемент, свободная ничего не хватает: система перестаёт утверждать
что-либо, вместо того чтобы угадывать.

**Но на быстром движении эта же политика ломает бросок.** Там неуверенных кадров
большинство, они голосуют за покой, поза застревает в бездействии, `closure` 0.6
не проходит ни один порог — и отпускания не наступает вовсе. Поэтому политика
зависит от движения: пока рука летит, планка падает с 0.75 до 0.65 и неуверенный
кадр перестаёт голосовать за покой. Смаз на махе — ожидаемое условие съёмки,
а не повод молчать.

Отдельно от политики: **бездействие больше не перебивает жест, который наблюдался.**
Жесту достаточно трёх кадров окна, покою по-прежнему нужно четыре. «Ничего» —
это не довод против «чего-то»: жест, который видели три раза из шести, сообщает
больше, чем столько же кадров его отсутствия.

Третья строка показывает, зачем неуверенному кадру всё же занимать место в окне:
без этого окно перестаёт быть окном по времени, растягивается на сколько угодно
кадров назад, и уверенная ошибка живёт дольше, чем должна.

### Переобучение под своего человека

Модель обучена на одном человеке. Для другого её лучше переобучить:

```bash
# 1. открыть record.html и пройти запись: 8 классов, два круга
# 2. положить полученный файл в data/
npx tsx scripts/build-gesture-model.ts data/gestures-v1.json
DROP=thumb,pinch ABSORB=thumb,pinch npx tsx scripts/eval-gestures.ts data/gestures-v1.json
```

Второй круг записи в обучении не участвует — на нём считаются цифры выше.
Добавление жеста не требует изменений в пайплайне: жест — это данные.

## Объём сцены

Доска не плоская: её плоскость наклонена на 26°, дальний край уходит к горизонту,
элементы и сетка получают настоящее перспективное сжатие.

Опасное место здесь ровно одно — **попадание по элементам**. Прицел живёт в экранных
координатах, элементы в мировых, и перевод между ними делает `screenToWorld`. Если бы он
разошёлся с тем, что рисует браузер, прицел брал бы не тот элемент, который под ним виден, —
отказ, который выглядит как «плохо распознаёт руку», хотя распознавание ни при чём.

Поэтому проекция задана один раз и в двух местах одними и теми же числами: слой мира
получает `rotateX(BOARD_TILT_DEG)`, его родитель — `perspective: BOARD_PERSPECTIVE`.
CSS `rotateX(θ)` переводит точку `(0, v, 0)` в `(0, v·cosθ, v·sinθ)`, а `perspective`
делит на `(D − z)`; `worldToScreen` считает ровно это, а `screenToWorld` выведен
обращением:

```
v = py·D / (D·cosθ + py·sinθ)
```

Проверяется это не на глаз, а свойством: `screenToWorld` обязан быть точным обратным
к `worldToScreen` — на сетке мировых точек и на сетке экранных пикселей, при разных
камерах и углах. Пока свойство держится, попадание верно **по построению**. Сверх того
есть браузерная проверка: клик по видимому центру стикера берёт именно его.

Сетка лежит внутри плоскости доски, а не на экране, — наклон и масштаб достаются ей
от слоя мира. На слое мира намеренно нет `transform-style: preserve-3d`: он завёл бы
3D-контекст, в котором браузер сортирует по глубине и перестаёт слушать `z-index`,
а порядок перекрытия элементов ведёт `el.z`.

Замер `scripts/measure-fps.ts`, два прогона подряд на одной машине: **155.7 FPS
с наклоном против 155.2 без него** — перспективное деление не стоит ничего.

Побочное следствие, которое стоит знать: магнитный фокус задан в мировых единицах,
поэтому у ближнего края его экранный радиус больше, чем у дальнего. Это заметил
упавший смоук — точка, которая была пустой при плоской доске, попала в магнит.

## Архитектура

```
src/contracts/input.ts   контракт событий, единственная точка стыковки модулей
src/shared/              emitter, константы, MouseInput — эмулятор жестов мышью
src/motion/              камера: точки, признаки, фильтр, машина состояний, подсказки
src/gestures/            признаки в координатах ладони, kNN, голосование
src/board/               холст, элементы, прицел, захват, падение, бросок, зум
src/pocket/              карман и режим подготовки
src/voice/               голосовой ввод текста
src/app/                 онбординг, калибровка, обучение, челлендж, финал, рекорды
src/dataset/             запись датасета жестов
```

Потребители знают только `InputSource` из `src/contracts/input.ts`. Доска не
импортирует ничего из `src/motion`, камера — ничего из `src/board`.

Практическое следствие: **весь интерфейс разрабатывался и тестировался на
эмуляторе жестов мышью**, а камера подключилась одной строкой. Поэтому вся
логика — доска, карман, челлендж, подсказки — покрыта обычными unit-тестами
без браузера и без камеры: 551 тест, 50 файлов.

Тот же шов работает и на вырост: заменить `HandLandmarker` на `PoseLandmarker`
с `numPoses > 1` — значит получить несколько человек и позы тела, не трогая
ничего выше контракта.

## Как это проверялось

- **551 unit-тест** на чистой логике: геометрия, физика, машина состояний,
  фильтр, голосование, карман, челлендж, подсказки.
- **Прогон по всему функционалу с записью видео**: `npx playwright test --project=walkthrough`
  проходит старт, все семь шагов обучения, панораму, зум, карман, диктовку,
  челлендж и финал, складывая в `test-results/` ролик и раскадровку. Сделан ради
  самой записи — на демо это запасной ролик, если не встанет камера или не будет света.
- **Playwright-смоук** на эмуляторе мыши и на записанном видео жестов,
  подаваемом как фейковая веб-камера Chrome.
- **Отложенный круг записи** для оценки классификатора — данные, на которых
  он не обучался.
- **Замер FPS под нагрузкой**: `scripts/measure-fps.ts` гоняет доску с 50
  элементами под непрерывной панорамой и зумом в видимом окне и сравнивает
  варианты оформления между собой в одном чередующемся прогоне. Так нашлась
  и была исправлена главная просадка: `filter: blur` на тени каждого элемента
  давал 41 FPS, радиальный градиент с размытием только под поднятым элементом —
  57 FPS.

## Ограничения

- **Модель обучена на одном человеке и на одной руке.** Второе выяснилось замером,
  а не догадкой: в одной из записей вторая половина была снята другой рукой, и
  обучение с правой на левую **не переносится вообще** — щипок, указательный и жест V
  дали ровно 0 % recall, все кадры ушли в бездействие. Значит зеркалирование признаков
  в `palmBasis` не приводит две руки в одно пространство, как задумывалось. Обходится
  тем, что в датасете есть обе руки, но для нового человека запись нужна заново:
  `record.html`, четыре минуты, потом `scripts/build-gesture-model.ts`.
- **Датасет надо писать в тех же условиях, в которых система работает.** Модель,
  снятая на Mac, на Windows не узнавала раскрытую ладонь, и элемент нельзя было
  выпустить из руки. То же касается разрешения: запись на 640×360 при камере 720p —
  та же ошибка, только незаметнее.
- **Частота кадров ограничена распознаванием, а не камерой.** 62 мс на вызов детектора
  при 1280×720 запирают цикл на 16 кадрах в секунду, и две руки стоят столько же,
  сколько одна. Кадр 640×360 даёт 23 кадра в секунду, но ложные действия на бездействии
  растут с 2.2 до 28.3 %: мелкой кисти не хватает пикселей. Размен отклонён по замеру.
- Undo не подключён: после «положить в карман» он дублировал бы элемент.
- Щелчок «кулак → ладонь» на резком махе вне зоны кармана удаляет элемент — это объясняется в обучении.
- Голосовой ввод требует Chrome и сети; без него текст готовится заранее.
